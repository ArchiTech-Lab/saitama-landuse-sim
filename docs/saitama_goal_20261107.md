# 埼玉県 土地利用シミュレーション — /goal（完成の定義）v2

## ゴール
**「コンパクトシティ極限（各Xで残った駅のコア円に全員が住む）にしたとき、埼玉県の土地は農地・工業・緑地にどう配分されるか」に、X・Y・Zを動かして答えられる単一HTMLを公開する。数字の根拠を聞かれたら、ページ内の仮定とリポジトリのスクリプトで答えられる状態にする。**

画面が答える問い（3つ）
1. Xを上げると、居住・農地・工業・緑地の面積比はどう変わるか
2. どのYで農地側が「全域を覆う（区分が意味を失う）」か＝被覆率が95%を超える最小のY（刻み15/30/45＋任意値）
3. 工業地帯（ICからZ分以内∧国道沿線100m以内）はどこに、どれだけあるか（セル数ベースと国道100m帯の実面積）

## 用語の確定（ここがぶれると検証できない）
| 用語 | 定義 |
|---|---|
| 駅勢圏の中心 | 名寄せ後の駅点（`build_real.py` の S）。生存駅のみ |
| 居住 | 生存駅のコア円（r=1200m）の和集合。それ以外に住宅区分は作らない |
| 撤退地域 | 生存駅に吸収されなかった（unreachable）セル。土地区分は通常どおり農地/工業/緑地に塗る |
| Y分 | 生存駅の中心からの車の最短所要時間。県外の生存駅も始点に含める。刻み15/30/45（既定30）、スライダー5〜60分 |
| Z分 | IC（OSM motorway_junction、JCT除外、スマートIC含む＝既定）から一般道での最短所要時間。刻み5/10/15（既定10）、スライダー1〜30分 |
| 工業地帯 | tI<=Z かつ 国道沿線100m帯が500mセルにかかる（nh100>0）。国道＝OSM（trunk で ref 1〜507、または name/official_name に「国道」を含む trunk/primary/secondary）の元の線を6677でバッファ。500m格子のため面積を過大評価するので、実面積＝工業セルのΣ nh100/100×0.25km² を別掲 |
| 格子 | 500m（標準地域メッシュ4次）。県内判定はセル中心で N03 県境内。L03-b の河川・湖沼が過半のセルは「区分外」 |
| 区分の優先 | 区分外（水域）＞ 居住 ＞ 工業 ＞ 農地 ＞ 緑地・森林。工業＞農地で固定（競合区分と切替UIは廃止。コード3は欠番） |

## 設計の確定（v1からの変更）
- **HTMLには区分マップでなく「時間場」を載せ、区分はブラウザで閾値判定する。**
  区分マップの前計算は 11X×3Y×3Z×3速度＝297枚（約13MB）で破綻する。時間場なら
  駅用 11X×3速度 ＋ IC用 3速度＝36枚×約1.5万セル×1byte（分）≒0.5MB。Y・Zは任意値のスライダーにでき、15/30/45・5/10/15は目盛りとして置く
- **完成を2段に分ける。**M1＝ローカル完成（公開判断の材料がそろう）／M2＝公開（本人承認後）

## M1 合格条件（`src/saitama_check.py` が全項目 PASS を出すこと）
判定は人の目でなくスクリプトの PASS/FAIL で行う。メインはこの出力だけを読む。

**正しさ**
1. 面積保存：区分別面積＋区分外＝県内格子の総面積。県内格子の総面積と N03 県面積の差 ≦2%（セル中心判定の誤差）
2. 入れ子：全X・全速度で Y15⊂Y30⊂Y45、Z5⊂Z10⊂Z15
3. 単調性：埼玉の生存駅数・居住面積がXに対して単調非増加
4. 整合：同じX・r の埼玉県内の生存駅数が、公開中の `honshu-station-density` の計算結果と一致
5. 二重実装の一致：Python の区分判定と HTML(JS) の区分判定が、代表27組（X3×Y3×Z3）で全セル一致
6. 投影：距離・面積の計算は EPSG:6677 のみ（コード中に 3857・緯度経度での面積計算がない）
7. 妥当性：道路版の所要時間と「直線距離×迂回率」の差の中央値を記録し、迂回率を較正（1.05〜1.6 の範囲外なら FAIL＝道路の焼き付けを疑う）

**機能・品質**
8. 区分（居住・工業・農地・緑地）＋区分外、X（11段階）・Y（15/30/45）・Z（5/10/15）のボタンとスライダー、速度プリセット3種が動く
9. 指標パネル：区分別面積（km²・%）、農地側・工業側の到達圏被覆率（居住を除く）、工業の実面積（国道100m帯）、生存駅数、撤退地域面積。農地側の被覆率が95%を超えたら「飽和」と表示
10. 切替の応答 ≦100ms（ヘッドレスで計測）、単一HTML ≦3MB、外部通信ゼロ、幅375pxで横スクロールなし
11. ヘッドレスのスクリーンショット3枚（低X・中X・高X）を `docs/shots/` に保存し、メインが1回だけ目視

**再現性・出典**
12. `src/` だけで 取得→計算→HTML 生成が再実行できる（取得URL・取得日を `data/saitama/manifest.json` に記録、キャッシュ再利用）
13. ページ内に表示：出典（国土数値情報 N02・N03・L03-b、国勢調査メッシュ、OSM）、速度の仮定値、限界（主要道のみ・渋滞なし・食料自給は未算出）
14. 結果の要約 `docs/saitama_result_YYYYMMDD.md`（問い1〜3への答えを数字で）とマスターの更新ログ

## M2 合格条件（公開・本人承認後のみ）
15. **公開前の確認事項を本人に提示して承認を得る**：新規リポジトリ名（案 `ArchiTech-Lab/saitama-landuse-sim`）／OSM由来データを埋め込むため ODbL の表示義務と派生DBの共有条件／コードのライセンス（既存に合わせMIT）
16. Pages の公開URLが HTTP 200、スマホ実機またはヘッドレスのモバイル幅で表示確認

## スコープ外
食料自給率・収量・経済価値／埼玉以外／渋滞・時間帯・公共交通での到達／将来推計の再計算／Y・Zの組み合わせの最適化
